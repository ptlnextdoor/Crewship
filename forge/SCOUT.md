- [Stale Instruction Files Override the Code in Coding Agents: A One-Sentence Fix](https://arxiv.org/abs/2610.30571) (arXiv cs.SE, 2026-10-22): 320 runs of Claude Code and Codex CLI on 40 projects whose CLAUDE.md/AGENTS.md contradicts the code; agents followed the stale file in 90.1% of choices (Codex rewrote working code in 20/80 runs, tests then failed in 17), one sentence giving existing code precedence moved them to 91.4% code-following and 100% test pass. Our builder reads AGENTS.md and LEARNINGS.md every session and both go stale (steward step 4 exists because of it); adding the sentence to `prompts/builder.md` is the whole change. Effort S. Implemented, see PR below.
- [Your AI agent fixed the bug, but what else did it change?](https://blog.trailofbits.com/2026/10/21/your-ai-agent-fixed-the-bug-but-what-else-did-it-change/) (Trail of Bits blog, 2026-10-21): two open plugins, patching-bugs and regression-hunt; regression-hunt traces the diff to callers, reproduces each candidate live, replays it in a fresh-context agent, then adjudicates; 25% fewer false positives than "review the PR for regressions" on 21 confirmed regressions. Reusable idea for us: the "three-arm proof" (original fails, patched passes, full revert fails again) as a reviewer check on bug-fix tickets, and an explicit written definition of what is not a regression (latent, pre-existing, incomplete fix) so the reviewer does not reject on those. Effort S for the prompt line, M to make the reviewer actually run the revert.
- [SWE-VERIFIER: Selective Verification for Cost-Efficient Coding Agents](https://arxiv.org/abs/2610.30284) (arXiv cs.LG, 2026-10-21): a 4B model scores each proposed agent action, triggers candidate sampling and re-ranking on under 4% of steps; +1.7 to +1.8 points resolution at 1.09 to 1.13x cost on mini-swe-agent. Would need a hook inside the harness (omp) at the action level; nothing we can bolt on from forge.py. Effort L, not now.
- [OpenShell: a safe, private runtime for fleets of autonomous AI agents](https://github.com/NVIDIA/OpenShell) (GitHub via HN 372 pts, 2026-10-22): Rust sandbox runtime; kernel-level file/syscall/network policy per agent, credentials injected only on approved endpoints, policy changes checked by a prover before apply. Our lanes run as the owner's user in worktrees with real credentials in env; moving builder lanes into sandboxes would remove the "builder leaks a key or runs rm -rf outside its worktree" class of failure. Effort L (Docker/Podman plus policy authoring per project).
